# 两个开源记账项目，哪些适合我们借鉴

研究日期：2026-10-01。目标是完善“小小账本”：日本使用、日元现金、手机本地数据、中文和日文切换、奶油白与鼠尾草绿、考拉装饰、按自然月独立的分类预算，以及任意日期记账。

本次查看了两个项目的关键源码、相关测试及仓库提供的部分图片，做了日期查询复核。没有安装运行这两个 App，也没有运行它们的完整构建或测试。下面区分源码中的现有做法与给我们提出的建议。

**我最建议先借鉴的四项**

| 顺序 | 借鉴内容 | 在我们的 App 中怎样使用 |
| --- | --- | --- |
| 1 | 本地备份与恢复 | 把账目、每月预算、分类和设置保存成完整备份；恢复前显示内容概要，并先保存当前账本。 |
| 2 | 金额输入与快捷入口 | 打开“记一笔”就能输入金额；提供适合整数日元的数字键盘，之后可加入加减计算和“保存，再记一笔”。 |
| 3 | 自定义分类 | 分类可以改名、排序、换图标；用固定编号关联账目，方便中日文切换，改名也不影响历史统计。 |
| 4 | 分类预算提醒 | 接近预算时温和提示，超支时显示具体金额；每个月的预算仍分别保存。 |

这些是下一轮建议，还没有进入新的 APK。已经交付的 0.1.0 包含月度/年度汇总、分类统计、每月分类预算及任意日期记账。

**Cashbook：数据、预算和记账细节很值得研究**

本次源码版本为 [`86de91515f07c96f82eb520176b0faa44a5f39b4`](https://github.com/WangJie0822/Cashbook/tree/86de91515f07c96f82eb520176b0faa44a5f39b4)，提交日期 2026-08-29。它使用 Kotlin，应用模块配置了 Compose；数据使用 Room 数据库，并有明确的数据库升级路径。对我们最有帮助的是将界面、计算与保存分别组织，之后改外观时也能继续复用记账规则。[应用配置](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/app/build.gradle.kts)，[数据库配置](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/database/src/main/kotlin/cn/wj/android/cashbook/core/database/di/DatabaseModule.kt)

| 源码中看到的做法 | 对我们的价值与调整 |
| --- | --- |
| 新增记录会自动显示金额输入；保存期间用状态阻止重复提交。 | 减少打开 App 后的操作，避免连续点保存产生重复账目。采用直接输入金额、醒目的保存按钮和明确的失败提示。[记账状态处理](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/feature/records/src/main/kotlin/cn/wj/android/cashbook/feature/records/viewmodel/EditRecordViewModel.kt#L284) |
| 自带数字与运算键盘。 | 适合把同一次购物的几项金额加起来。我们先考虑加减与退格；保存金额必须是正整数日元，计算结果出现小数时应让用户调整，避免默默取整。[键盘计算](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/design/src/main/kotlin/cn/wj/android/cashbook/core/design/util/CalculatorUtils.kt) |
| 分类有独立 ID、名称、图标与排序值；删除有账目的分类时，页面会提示先把记录移动到其他分类。 | 我们需要同样稳定的关联关系，并补上中文/日文显示名称。已有账目的分类建议优先隐藏；确需合并时一起更新历史账目和相关预算，防止漏算。[分类数据](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/database/src/main/kotlin/cn/wj/android/cashbook/core/database/table/TypeTable.kt)，[删除流程](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/feature/types/src/main/kotlin/cn/wj/android/cashbook/feature/types/viewmodel/MyCategoriesViewModel.kt#L177) |
| 预算分正常、接近与超支三种状态；80% 起进入接近状态，超过 100% 时显示超支金额。 | 首页正常时用鼠尾草绿，接近上限时用柔和的暖色并附文字，超支时写清“超出 ¥…”。颜色只是辅助，不依赖颜色传递全部信息。[预算状态](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/model/src/main/kotlin/cn/wj/android/cashbook/core/model/entity/BudgetProgressEntity.kt#L56) |
| 备份带格式版本；恢复前解压到缓存，检查允许的内容与大小，对较新的不支持版本拒绝恢复，并先留一份当前数据库及图片副本。 | 学习版本检查和恢复前留副本的顺序。我们的完整备份还必须包含按月预算与中日文分类。恢复先预览记录数、日期范围、货币和版本；失败时保持原账本可用。[备份恢复实现](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/data/src/main/kotlin/cn/wj/android/cashbook/core/data/uitl/impl/BackupRecoveryManagerImpl.kt#L743) |
| CSV 导出使用 UTF-8 BOM，并处理备注中的逗号、引号和换行。 | 适合把明细拿到电脑查看。我们要输出 JPY 整数和原始备注；CSV 只用于明细查看，完整恢复使用另一个包含预算、分类与设置的备份文件。[CSV 导出](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/data/src/main/kotlin/cn/wj/android/cashbook/core/data/helper/DailyAccountExporter.kt#L47) |

有三处需要按我们的需求另行设计：

- Cashbook 的预算表以“账本 ID＋分类 ID”唯一关联，没有月份字段。我们的预算应以“月份＋分类 ID”唯一关联，保留每个月独立修改的能力。[预算表](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/database/src/main/kotlin/cn/wj/android/cashbook/core/database/table/BudgetTable.kt#L34)
- 它的金额及 CSV 导出使用人民币的分/元换算和 CNY。我们的金额直接以整数日元保存与累加，界面明确标注 JPY。[预算金额解析](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/model/src/main/kotlin/cn/wj/android/cashbook/core/model/model/BudgetAmount.kt)，[CSV 金额](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/data/src/main/kotlin/cn/wj/android/cashbook/core/data/helper/DailyAccountExporter.kt#L65)
- 恢复数据库时，它采用合并并替换同主键记录的方式，当前库中其他记录仍保留；恢复前副本用于人工回退。我们需要让用户清楚知道恢复的结果。第一步建议做“预览后恢复完整快照”，并在实现中检查失败回滚，之后再讨论合并导入。[恢复语义](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/database/src/main/kotlin/cn/wj/android/cashbook/core/database/migration/DatabaseMigrations.kt#L86)

**easy_write：年月选择、图表和桌面入口适合参考**

本次源码版本为 [`746b958a6a8bc493feff0755b5941d2a9ed5abb3`](https://github.com/wilinz/easy_write/tree/746b958a6a8bc493feff0755b5941d2a9ed5abb3)，提交日期 2025-03-02。它包含 Kotlin/Compose 页面、Room 本地数据库与网络服务。手动录入表单有金额、分类、日期、名称、商户/来源与备注；对你来说可以把最常用的金额、分类、日期放前面，其他内容按需展开。[录入页面](https://github.com/wilinz/easy_write/blob/746b958a6a8bc493feff0755b5941d2a9ed5abb3/app/src/main/java/com/eazywrite/app/ui/bill/BillEditPage.kt#L247)

| 源码中看到的做法 | 对我们的价值与调整 |
| --- | --- |
| 年月选择器可以切换年份，再从月份网格中选月。 | 年份和 12 个月放在同一个入口，减少反复点“上一月”。沿用我们已有的年度汇总、月份明细，并保留“今天”按钮。[年月选择器](https://github.com/wilinz/easy_write/blob/746b958a6a8bc493feff0755b5941d2a9ed5abb3/app/src/main/java/com/eazywrite/app/ui/wiget/YearMonthPicker.kt#L123) |
| 图表按年显示各月趋势，按月显示各日趋势，并分别组织收入、支出及分类占比。 | 以后给年度页加简洁收支柱形图，月度页加每日支出趋势；点击分类金额能进入对应明细。图表与上方金额要共用同一批记录和统计规则。[图表数据](https://github.com/wilinz/easy_write/blob/746b958a6a8bc493feff0755b5941d2a9ed5abb3/app/src/main/java/com/eazywrite/app/ui/chart/ChartViewModel.kt#L44) |
| 桌面小组件有查看与新增账目的直接入口。 | 很适合现金支付后顺手记一笔。后续可做小型考拉组件，只显示“记一笔”和本月支出；具体尺寸和是否显示金额再一起选择。[桌面入口](https://github.com/wilinz/easy_write/blob/746b958a6a8bc493feff0755b5941d2a9ed5abb3/app/src/main/java/com/eazywrite/app/ui/bill/DesktopAppWidget.kt#L100) |

它的账目新增、修改与删除会调用服务器，新增时还要求当前用户，服务器返回后才写入本地。这条路径不符合我们纯本地、随时手动记录的需求；可以学习页面组织方式，保存流程由我们围绕本地数据实现。[账目仓库](https://github.com/wilinz/easy_write/blob/746b958a6a8bc493feff0755b5941d2a9ed5abb3/app/src/main/java/com/eazywrite/app/data/repository/BillRepository.kt#L32)

日期复核也给了我们一个具体提醒：日趋势生成使用 `date.month.maxLength()`，二月返回的是最大可能天数 29；在 2025 年会生成从 2 月 1 日到 3 月 1 日的 29 个日期。我们的图表要根据选中年份使用实际天数。该项目的月度图表汇总查询已经使用结束日期不包含的规则，因此这个观察针对日趋势日期生成，不能据此说它的全部月度汇总都会多算。[日趋势日期生成](https://github.com/wilinz/easy_write/blob/746b958a6a8bc493feff0755b5941d2a9ed5abb3/app/src/main/java/com/eazywrite/app/ui/chart/ChartViewModel.kt#L89)，[汇总查询](https://github.com/wilinz/easy_write/blob/746b958a6a8bc493feff0755b5941d2a9ed5abb3/app/src/main/java/com/eazywrite/app/data/database/BillDao.kt#L130)

**落到我们自己的实现**

目前 0.1.0 测试版的安卓外壳是 Java，界面是打包在手机里的本地 WebView，数据用带版本的 JSON 文件保存；它尚未使用 Kotlin/Compose。Cashbook 和 easy_write 的 Kotlin 页面不能直接放入现有界面使用，但其记账流程、数据关联、预算计算与恢复顺序都可以借鉴。[当前项目说明](../README.md)

如果后续选择 Kotlin 原生版本，我建议使用 Compose 做界面、ViewModel 管理页面状态、Room 保存账目、DataStore 保存语言等设置，并保留少量清楚的功能划分：记账、统计、预算、设置。Cashbook 的细分模块很多，个人第一项目可以先用较小结构，随着功能增长再拆分。

无论继续完善现有测试版，还是以后迁移到 Kotlin，数据规则都应一致：

- 金额使用整数日元；收入/支出类型独立保存。
- 账目保存用户选择的日期，年份、月份与每日筛选都按这个日期计算；未来账目立即计入对应月份。
- “今天”使用日本时区；修改一笔账目的日期后，原月份与新月份同步重新计算。
- 分类使用稳定 ID，显示文字与中日文切换分开；自定义分类可以填自己的名称。
- 预算以月份和分类 ID 关联；未设置预算的分类仍计入总支出与分类统计。
- 完整备份保存账目、分类、全部月份预算与必要设置，带格式版本；CSV 用于查看明细。
- 数据格式或数据库升级前先有可恢复备份，再验证升级前后的账目数量、年月汇总与预算关联。

后续验证集中在真正影响账本的事情：月底和跨年、闰年二月、日本午夜、未来日期、跨月修改与删除、分类改名与隐藏、重复保存，以及备份损坏或写入失败时原账本仍完整。Cashbook 中已有日期周期、预算状态与备份格式等相关测试，可以借鉴测试场景。[日期测试](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/model/src/test/kotlin/cn/wj/android/cashbook/core/model/entity/DateSelectionEntityMonthCycleTest.kt)，[预算测试](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/core/domain/src/test/kotlin/cn/wj/android/cashbook/domain/usecase/GetBudgetProgressUseCaseTest.kt)

本次用虚构记录执行了 easy_write 的两个汇总 SQL：确认图表查询排除下月第一天，界面日期过滤包含用户选择的最后一天；也复核了普通年份和闰年二月的日期生成差别。这些检查支持上面的具体日期结论，不代表两个项目已经通过完整实机验证。

代码来源方面，Cashbook 的仓库包含 Apache-2.0 许可证；easy_write 的 README 标明 MPL-2.0，并另外写了非商业使用条款。本次未复制这两个记账项目的代码或图片。后续若直接复用代码，需要按各项目的许可处理来源和分发；自主实现交互与业务规则更适合目前的个人项目。[Cashbook 许可证](https://github.com/WangJie0822/Cashbook/blob/86de91515f07c96f82eb520176b0faa44a5f39b4/LICENSE)，[easy_write 项目说明](https://github.com/wilinz/easy_write/blob/746b958a6a8bc493feff0755b5941d2a9ed5abb3/README.md)

## 2026-10-01：已应用到 0.2.0

在现有测试版基础上自主实现以下改进，保持 Java 与离线 WebView 的结构：

- 直接展示金额键盘，支持整数加减、退格、清空与“保存，再记一笔”；保留用户输入直到成功写入。
- 分类拆成稳定 ID、中日文名称与图标，可排序或隐藏；分类改名后，历史账目和每月预算仍保持关联。
- 预算分正常、接近与超支状态；上月设置可以复制到当前月，之后的调整彼此独立。
- 年度收支图、月度分类环形图、每日趋势和分类明细共用所选日期的账目；二月根据实际年份生成日期。
- 完整备份带格式版本，包含全部月份、分类和设置；恢复前展示内容并保留当前账本副本，可撤销上次恢复。
- CSV 使用 UTF-8 BOM，转义逗号、引号和换行，金额输出整数 JPY；完整恢复使用 JSON 备份。
- 旧格式首次写入升级前保留原文件副本；读取失败时阻止直接覆盖；历史账目 ID 不复用。

另行阅读了 [Ivy Wallet 的产品介绍](https://github.com/Ivy-Apps/ivy-wallet)，参考其手动记账、大金额与清楚的收支信息层次；阅读了 [My Expenses 的数据说明](https://github.com/mtotschnig/MyExpenses/wiki/FAQ:-Data)，用于梳理备份、换手机和导出用途。对这两个项目仅参考产品与文档，本轮没有深入审查其完整源码。

文件选择与保存按 [Android 官方 Storage Access Framework 文档](https://developer.android.com/training/data-storage/shared/documents-files) 实现，不要求广泛存储权限。UI 图标单独采用 Lucide 0.468.0，已随应用打包并保留 ISC 许可证；考拉和其他界面装饰由本项目代码绘制。

本轮通过 19 项领域检查、19 个浏览器操作场景和 11 项 Java 数据校验测试。验证涵盖迁移、日期边界、未来账目、预算独立性、分类关联、写入失败、恢复撤销与中日文布局。浏览器中的安卓接口使用模拟实现；这些结果不等于 X300 Pro 实机、安卓文件选择器或设备内部写入已经验证。
