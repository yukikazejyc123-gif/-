# 小小账本开发指引

本文件适用于这个安卓项目。开始修改前先阅读 [项目上下文](docs/PROJECT_CONTEXT.md) 和 [README](README.md)，延续已确认的产品行为与设计方向。

## 开发入口

- 当前架构为 Java 17 + Android WebView。页面、逻辑、图片、字体均在 APK 内；不要把当前实现误写为 Kotlin/Compose。
- 领域规则：`app/src/main/assets/ledger-core.js`；界面：`ledger-ui.js`、`ledger-en.js`、`ledger.css`。
- 原生入口、存储及 WebView 白名单：`MainActivity.java`；数据校验：`LedgerValidator.java`；汇率：`ExchangeRateClient.java`，均位于 `app/src/main/java/com/koalaledger/app/`。

## 必须保持的行为

- 手机首次安装是空账本。演示数据只供预览，不能写入真实账本。
- 首页点日期切换明细的操作保留；过去、未来都能记账，未来记录按普通账目计入对应月份。“今天”按 `Asia/Tokyo` 返回当天。
- 考拉眨眼、弹跳、挥手和「＋1」只是装饰，不添加账目、不改收入或金额。动画保持轻快，支持应用关闭动画及系统减少动态效果。
- 多账本的记录、分类、月预算、主币及账本内汇率各自独立；语言与外观偏好是全局设置。新建、改名和切换都要处理保存失败回滚。
- 金额使用最小货币单位整数；日元、韩元没有小数，其余支持币种两位小数。精确换算与舍入必须在 JS 和 Java 校验中保持一致。
- 改主币时原币金额不变，账目与预算一起换算，并保留历史快照；修改备注、分类或日期不能丢掉换算历史。
- 数据格式 5 包含多个格式 4 账本；旧格式 1–4 迁入默认账本。迁移保留 ID、日期、备注、分类、金额、预算及已有汇率记录。
- 完整备份包含全部账本；恢复替换全部账本，必须明确展示范围并保留恢复前快照。CSV 只导出当前账本，不能当完整备份恢复。
- 读取失败不能覆盖原数据；保存走原子写入。不要绕过原生数据校验、资源白名单或内容安全策略。
- 联网只获取货币对报价，不发送账单金额、备注、分类或日期；保留缓存和手动汇率入口。

## 界面与文案

- 延续奶油白、鼠尾草绿、圆润纸面、清晰层次与可爱考拉；保留统一插画图标库与应用内选择面板。
- 修改图标时检查裁切、视觉居中与背景留白；修改布局时检查长名称、长金额、弹窗、滚动和 320/360/412 像素宽度。
- 系统文案支持中文、日文、韩文、英语；新提示同步四种语言。用户填写的账本名称与备注原样保留，自定义分类缺少翻译时按既有规则回退主名称。
- 日文使用内置 Zen Maru Gothic，韩文使用内置 Noto Sans KR；中文与英语保持清楚的系统字体。避免无必要的辅助提示与重复文字。

## 验证与交付

构建环境为 JDK 17、Android SDK Platform 35、Build Tools 35.0.0，使用项目内 Gradle Wrapper。在项目目录运行：

```powershell
.\gradlew.bat assembleDebug lintDebug testDebugUnitTest
```

Java 单元测试在 `app/src/test/`。随源码提供的反馈浏览器测试在 `tests/ui-feedback.test.cjs`，安装 package.json 中的依赖和 Playwright Chromium 后运行 `npm test`，具体命令见 README。其余既有 JS、浏览器回归及发布校验脚本保存在开发工作区的 `work/`，没有随 GitHub 源码发布；新克隆不能假设这些旧脚本已存在。领域规则变更应同时验证 JS/Java，一般界面变更要做实际浏览器资源检查。电脑检查与实机检查分开记录，不把模拟存储或截图当手机安装测试。

不提交签名私钥、认证信息、真实账本、备份、本机 SDK 路径或构建缓存。保留图标和字体许可；没有作者本地签名私钥时沿用默认 debug 签名，自行构建包不能直接覆盖作者测试包。
